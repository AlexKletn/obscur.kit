Whether Tab stops on `node`.

Three questions, and the first is the load-bearing one: the role must be
interactive, by the SAME derivation the accessibility projection uses. A
control a screen reader is told it can focus and a control Tab refuses to
reach would be two truths about one node.

Authored `tabindex` is not modelled — nothing in the view model carries one —
so every stop sorts equal and the ring is pure document order. `FocusNode`
and `TabOrder` already understand a tab index; giving them one here would mean
inventing an attribute no author can currently write.
