# 12 — What is not wired

A type existing is not evidence that anything calls it, and a doc comment
asserting the wiring is not evidence either. This page is the list of things that
compile, pass their tests, and have **no production caller** — plus the things
that are real but stop at a named boundary.

**Method.** For each entry: grep the symbol across `crates/`, excluding its own
crate and excluding `tests/`. A crate-level entry additionally checks which
`Cargo.toml` files depend on it. Verified at the commit that added this page;
it decays as soon as someone adds the caller.

---

## Unwired by construction: the re-export barrel

`obscur-kit/src/lib.rs` is `pub use X as y;` and nothing else. A crate whose only
path to the outside is that file is exported, compiles, and is called by nothing.

The table below is what the check found. Three rows are still that shape; the
fourth, `obscur-testkit`, used to be the worst of them and no longer is — it is
kept here so the correction is visible next to the claim it replaces.

| Crate | Depended on by | Verdict |
|---|---|---|
| `obscur-routing` | the facade barrel only | **unwired** — no runtime consumer |
| `obscur-windowing` | the winit and layer adapters + the barrel | **partly wired** — its `layer` module is what `LayerApp` is configured with. The older `Window` / `WindowProperties` still have no consumer: `App` uses winit's own types |
| `obscur-system` | the four platform adapters + the barrel | **host-wired** — `KitBootstrap::system_shell_provider()` hands one over; nothing in the runtime calls it |
| `obscur-testkit` | `obscur-runtime`'s test targets, as a dev-dependency | **wired, for tests only.** This entry used to read *"unreachable by construction — depended on by nothing, and not re-exported"*, and that was true of a 49-line skeleton of eleven unit structs. It is now the §2.4 harness — 36 files, ~1,900 lines, 131 public items across `fixture/`, `selector/`, `assertion/`, `mock/` and `host/` — and its **first and so far only consumer is `obscur-runtime`'s own suite**: the 26 files under `crates/application/obscur-runtime/tests/` (233 tests) that the runtime-decomposition campaign moved out of `ui_runtime.rs`, plus a few unit tests still in `src/` that borrow the parts they can reach. It is still deliberately **not** re-exported from the facade: nothing a host ships depends on it, and `PluginTestHost` is still a stub because nothing drives plugin activation through a harness yet. Note the limit the crate boundary imposes: `UiRuntime` is built twice in `obscur-runtime`'s own test target (the library `obscur-testkit` links, and the library under `--test`), so the fixtures that *name* a `UiRuntime` are reachable from `tests/` only, and the unit tests in `src/` can borrow just the parts whose types come from elsewhere — views, stylesheets, pointer events, display lists, key/pointer events, resource providers, `BlockingExecutor` |

## Zero-caller types

| Symbol | Notes |
|---|---|
| `IntrinsicMeasure` | the layout port leaves are documented as routing to. They do not |
| `StyleCache`, `LayoutCache` | dead; both *could* genuinely be wired |
| Vello `GlyphCache` / `PathCache` / `TextureCache` | dead scaffolding — Vello's own atlases make them redundant. To delete, not to bound |
| `GamepadEvent`, `GamepadButton`, `GamepadAxis`, `GamepadId` | modelled; nothing produces one |
| `HapticRequest`, `HapticPattern` | modelled; nothing consumes one |
| `FocusTree`, `FocusRestore`, `SpatialNavigation`, `NavigationDirection` | ~~focus traversal; **Tab does not move focus**~~ — **`TabOrder` is wired**: Tab and Shift+Tab walk the interactive roles, an open trapping `FocusScope` narrows the ring, and keyboard focus sets `:focus-visible`. These four are what is left: the ring is computed from the retained tree on demand, so `FocusTree`'s registration model answers a question nothing asks; nothing saves or restores a focus position across a dialog; and arrow keys belong to the editing session, so spatial navigation needs a "when is this a grid" rule that does not exist |
| `GestureArena`, `GestureContender` | the runtime resolves gestures through its own state instead |
| `InjectionSink` | no shipped host installs one, so DevTools injection is always refused |
| `ReplaySession` and the record/replay tier | only a spec test drives it |

## Real, but bounded

| Area | Where it stops |
|---|---|
| **`@container`** | parses, then lowers to `RuleCondition::Never`. Fails closed — the rule never matches. Container query *units* resolve against the viewport |
| **`::before` / `::after`** | parse, then reported unsupported. Generate nothing, fail closed |
| **UA stylesheet vocabulary** | **Was: a third of the sheet matched nothing.** This page's own subject, in the one place a reader would never look for it — a *stylesheet* is not a type, so no grep for a zero-caller symbol would ever have found it. **Seven of the sheet's 48 rules** could not reach anything the Rust API builds: `table`, `th`, `td`, `tr:hover` against a widget whose rows and cells carried a private `role` *property* CSS cannot see; `img` against a primitive that emitted no name at all; `.placeholder` against a class nothing emits, when §4.16 makes the hint a synthetic part reachable only through `::part()`; `.select-option.disabled` against a per-option state `Select` does not have. All seven are closed, and `tests/ua_stylesheet_vocabulary.rs` now enforces the property rather than the instances: it **harvests** the vocabulary from real rendered frames — every widget and primitive in every state that emits a distinct name, part or class — and rejects any type, class, part, id or unreachable pseudo-class in the sheet that is not in that harvest. Where it stops: **`a` and `fieldset` have no widget and no primitive**, so those four rules reach hand-written markup only — nothing a program builds is ever an `<a>`. And the `select:disabled .select-option` rewrite is reachable in exactly one state — a control disabled while its popup is already open, since `Select::open` refuses on a disabled control. Full ledger: `docs/element-vocabulary-audit.md` |
| **Base-element control tags** | **Was: *"they bind to the shipped widget's `ComponentId`, but nothing registers a factory for the built-in widget ids, so the widget's own `view()` — its indicator sub-part, its `:checked` class — never runs. The id is a handle with nothing mounted under it."*** Five of the six now mount, and the sixth is a refusal with a reason. `<input>`, `<textarea>`, `<checkbox>`, `<radio>`, `<select>`, `<table>` bind to the shipped widget's `ComponentId` instead of falling through to `Container`, so an authored `<checkbox>` is a checkbox to the cascade, to hit-testing and to the accessibility tree. **`<checkbox>`, `<radio>`, `<select>`, `<input>` and `<textarea>` are now also mounted controls** — a `…Props` + `…Component` + `…Factory` trio ships in `obscur-widgets` for each, `KitBootstrap::install_builtin_components` registers them by default, and `App`/the layer runner call it. An authored `<checkbox label="…" checked/>` renders the `.checkbox-box` indicator the UA sheet fills, with `:checked` still matching the host; `<radio label="…" checked/>` renders its `.radio-dot`; `<select options="Alpha, Beta" open/>` renders the `.select-header` and the `.select-list` of rows, and a `<select … open disabled/>` still reaches `select:disabled .select-option`; `<input value="abc"/>` renders its editable run, where before an authored value was invisible. `<input>` and `<textarea>` are **one** registration — they share `Input::COMPONENT_ID`, and which of them a node is rides on its local name, so `EditableField::is_multiline` still tells them apart and an authored textarea's `Enter` still inserts a newline. **`<button>` is mounted too, and it is the one whose content is the author's**: `ButtonComponent` renders the §2.12 default-slot outlet with `label="…"` as its fallback, so `<button>Save</button>` keeps its text, `<button><span>press</span></button>` keeps its span, `<button label="Save"/>` finally renders the label the `.okui` compiler already required, and `Button::new("Save", cmd).view()` — which states the label as a child — renders exactly the tree it did before. Those first five own their content, so none of *them* needs slot machinery. **Owning it has a price, and it is now a compile error rather than a silent one:** a mounted component's output *replaces* its host's children, so `<textarea>Hello</textarea>` — HTML's spelling of a default value — would have rendered an empty field. `mounted_element_contracts()` gives those five tags a §2.13 `no_children` policy, so the markup reports and names the `value="…"` migration instead. Where it stops: **`<table>` is still a handle with nothing under it** — no props struct, no `Component`, no factory, so its `view()` does not run. That one is a decision rather than a gap: a table's rows and cells are `tr`/`td`/`th` elements the author writes or `Table::view()` generates from data, so a component mounted there could only render the outlet that hands them straight back — a mount that changes nothing. `<table>` stays an author-owned base element, and `builtin_components.rs`'s `the_table_id_is_left_unclaimed` says so from the outside. Neither `<table>` nor `<button>` is on that child-policy list, because both keep their authored children. `Menu`, `Dialog`, `Tabs`, `List`, `Tree` and `Docking` deliberately keep their one PascalCase spelling: the UA sheet styles none of them by type, and a lowercase tag no rule reaches would be vocabulary with nothing behind it |
| **`ch` units** | layout measures them; paint-side properties read absolute px, so a `ch` that reaches one contributes `0` |
| **Layer-shell keyboard** | `set_keyboard_interactivity` is sent, but no keys are delivered: there is no keysym→`PhysicalKey` table, and an approximate one would put *wrong* keys into an application. `Exclusive` is therefore worse than useless today — it takes the desktop's focus and forwards nothing |
| **Layer-shell popups** | `get_popup` is not exposed; a panel cannot open a menu. Needs xdg-popup alongside |
| **Layer-shell v5** | `set_exclusive_edge` is unreachable — SCTK 0.19 binds versions 1–4 |
| **Font enumeration** | Linux only. macOS and Windows have providers with no enumeration |
| **Font fallback** | per *run*, not per character; `.ttf`/`.otf` only, no `.ttc` collections |
| **Localization** | CLDR plural categories are real, with one production consumer (the shaper's language hint). Dates, numbers, currencies and the RTL frame path are open |
| **Accessibility** | outbound only, behind the non-default `accesskit` feature. Inbound (an AT driving the app) is not built |
| **§6.7 action model** | seven surfaces named; two exist (shortcuts, `Menu`). Custom context menus are required and unbuilt |
| **Components** | **Was: *"`register_component` mounts a factory, and nothing ships one"*** — the tier compiled, was spec-tested, and had no citizen: every `impl Component for` in the workspace sat either inside a `#[cfg(test)]` module (twelve of them) or inside `obscur-testkit`, the harness crate nothing but a test target depends on (three). authorable now: `<Card/>` binds to the id `#[derive(Contract)]` computes for that name, and `register_component` mounts a factory under it. **The tier also has production citizens at last**: `CheckboxComponent`, `RadioComponent`, `SelectComponent`, `InputComponent` and `ButtonComponent` — **five** `impl Component`s in a crate an application links, each with a `ComponentFactory` beside it — and `BuiltinComponents` is the first thing that registers factories a host did not write (five registrations, installed by default, refusable with `KitBootstrap::without_builtin_components`). `ButtonComponent` is the one whose render is not content at all — it is the §2.12 default-slot outlet, with the `label` prop as its fallback, so mounting it gives the author's markup back rather than replacing it. What stops is the *checking* — an unregistered or misspelled tag mounts nothing with no diagnostic, and the `okui!` macro cannot ever check it (the registry is a runtime value of trait objects; the macro runs while that crate compiles). And one thing a shipped widget cannot do: **use `#[derive(Contract)]`.** The derive expands to `::obscur_kit::…` paths and §3.16 forbids an internal crate from depending on the facade, so each `…Props::contract()` is written out by hand and pinned against the derive's own output by `obscur-kit/tests/builtin_components.rs`. The derive also could not express the decoding: a reserved boolean attribute is set by *presence* (`<checkbox checked/>` lowers to `Null`, which `:checked` reads as set and `decode_optional::<bool>` reads as absent), a checkbox has a third, mixed state no boolean carries, and a `<select>`'s options are a *list* — which a `ViewValue` has no variant for, so they travel as a delimited string that the props struct splits (comma-separated when authored, and joined on U+001F by `Select::view` so a Rust caller's label containing a comma still survives) |
| **`<VirtualFor>`** | compiles on both front ends and emits the §4.9 marker the runtime windows. The template carries **no item binding**, so every realized row is identical; per-item rows still need `register_virtual_list` |
| **Slots** | **Was: *"No shipped component declares a slot: no shipped widget is a `Component`."*** Both halves of that sentence are false now, and only the first half needed slots to fix it. Declared, enforced and projected. **One shipped component declares a slot, and it is the default one.** `Checkbox`, `Radio`, `Select` and `Input` declare none, and for a reason rather than an omission: each renders content of its own (a label, a dot, a list of rows built from labels, an editable run), so each contract is `ChildContract::None` and an authored child under one is a compile error naming the prop spelling instead. `Button` is the control where that answer was not available — `<button>Save</button>` is the author's own markup, and its only child is a *text run*, which carries no properties and so can never name a slot. So §2.12 gained the piece it was missing: **the default slot.** An outlet naming no slot takes the content that names none (text runs included); an outlet nothing fills renders its own children as a **fallback**, which is how `<button label="Save"/>` and `<button>Save</button>` are one component rendering one position; and `ButtonProps::contract()` declares that slot under the reserved `DEFAULT_SLOT` name, `SlotCardinality::Many`, `ChildContract::Any`. The retention gate moved with it: the reconciler kept a host's children only when one of them named a slot, which no default-slot content ever does, so it now also keeps them for any id a component can be mounted under (`may_project_content` — the widget range and the top-bit user range; every `div` in a document is a primitive below both). Two things that used to stop here no longer do. ~~"an outlet's *name* is checked against nothing, so a component rendering `<slot name="hedaer"/>` receives nothing"~~ — `SlotMismatch::find` compares both sides against the contract and `ComponentRenderPass` reports `view.undeclared_slot`, at the one point where both halves exist: after the render, before projection substitutes the outlets away. It is checked from the author's side too, since a misspelled `slot="…"` is dropped just as quietly. ~~"the spec still does not state the default slot — §2.12 lists 'named slots' only"~~ — §2.12 now states it: what it is, that a text run makes it necessary rather than convenient, that it is declared under a reserved symbol no author-written name can produce, and that names are checked against the contract. `#[derive(Contract)]` gained `slot(default)`, so `spec_ch2_contracts`'s `a_default_slot_and_a_named_slot_partition_the_children` is **restored** to its full form and `ButtonProps`'s hand-written contract is now compared to the derive's output *whole*. Where it stops: the default slot and outlet fallback content still have no authored spelling, so `.okui` refuses `<slot/>` and children on an outlet — with diagnostics that say why rather than saying the feature is absent |
| **Telemetry** | `PerformanceSpan` carries no duration; the DevTools protocol has no timing field. `OBSCUR_FRAME_STATS` is the honest profiler |
| **Diagnostics** | several producers construct a `Diagnostic` and drop it into the null sink. Reachable, not reached |
| **Invalidation** | per-node on the style phase; a boolean per phase everywhere else. The phases take no dirty set |
| **Docking** | panels are described and laid out; re-docking by drag is not built |
| **Plugin tier** | an honest, well-labelled, entirely unbuilt skeleton. The `sandbox` module *describes* a sandbox; it does not enforce one, and the crate docs say so |

## Known defects

| | |
|---|---|
| **Flex clamps its own border box** | a flex container clamps rather than overflowing, so `width: 100%` + padding gives a different used width under flex than under block. The chain `[1000, 1020, 960]` is internally inconsistent. Related and *fixed*: an `auto` basis now resolves to max-content, so a plain item no longer eats the free space its growing siblings asked for |
| **Indefinite axes and percentages** | percentages should resolve only against a definite size; the constraint model does not carry the distinction everywhere. Related and *fixed*: a percentage block-size resolved against the space a child's *siblings* had left over, compounding down the chain (two `height: 100%` siblings measured 240/0). Flow now attaches the containing block's own definite content size as `BoxConstraints::percent_basis`, separately from the offer. Also *fixed*: a grid item's children saw the grid **container's** content box rather than the item's grid area (a `width: 100%` item was its 211px track while its child resolved `50%` against 432), and grid now states each item's area as `LayoutOutput::child_percent_basis`. Also *fixed*, the same defect in flex: an item's cross size was measured with the main axis pinned to its used size and no basis, so a `width: 50%` item re-read that pinned number as its containing block and laid its own content out at half again (a wrapping inner row reported two lines, 120, where its arranged self has one, 60). The cross measure now states the flex container's content box, which is the number the item's main size was already resolved against. **Both of the remainders this row used to carry are now closed too.** (i) The grid states each item's area on **both** axes, not just the inline one — `specs/w3c/css-grid-2.txt:3527` is explicit that by the time items are laid out "each grid area's width and height are considered definite for this purpose", which answers by phase order the worry (a content-sized row's extent is the item's own height) that had kept the block axis unstated; a `height: 100%` item's child read 96, half the container's content height, where it should read half the item's 100px row (`tests/percentage_in_grid_item.rs`). (ii) A percentage against a genuinely indefinite axis now **behaves as auto** (`specs/w3c/css-sizing-3.txt:554`) instead of folding against the offer: flow states an indefinite block size as `f32::INFINITY`, which `Dimension::resolve` already answers `None` to, so the value arrives on the `auto` path every caller already had. Two `height: 50%` siblings under an `auto`-height parent measured `(225, 112.5)` — half the offer, then half of what that left — and now measure the `auto` answer, verified equal to the `auto` spelling rather than to a constant (`tests/percentage_against_indefinite.rs`). The rule now reaches the three intrinsic-sizing probes this row used to name: flex's `probe_main` states an infinite main basis (its comment used to read "this engine has no behave-as-auto"; it does now), and grid's step-2 item measure states `(area, ∞)` because the rows are sized *from* that measure and the block axis is genuinely indefinite at that moment. What remains is narrower than the heading: `min-content`/`max-content` as a *cross* size still reads as "not a length" and so is treated as `auto` where css-flexbox scopes stretch to "computed cross size is auto" — a separate sentence, separately open |
| **No real min/max-content pair** | intrinsic sizing computes one number where the algorithm wants two |

## What this page is not

It is not a roadmap and not an apology. Most of these are deliberate: failing
closed on `@container` is better than matching wrongly, and a CPU renderer that
approximates GPU effects by policy is better than one that pretends. The list
exists so that reading a type's presence in the re-export barrel does not mislead
you into thinking something runs.

If you need one of these wired, the gap is usually small and specific — most
entries above are "no caller", not "no implementation".
