# 12 — What is not wired

A type existing is not evidence that anything calls it, and a doc comment
asserting the wiring is not evidence either. This page is the list of things that
compile, pass their tests, and have **no production caller** — plus the things
that are real but stop at a named boundary.

**Method.** For each entry: grep the symbol across `crates/`, excluding its own
crate and excluding `tests/`. A crate-level entry additionally checks which
`Cargo.toml` files depend on it. Verified at the commit that added this page;
it decays as soon as someone adds the caller.

**Last re-measured 2026-08-04, at `628d7f40` plus the uncommitted debt-closure
working tree.** Method: every row re-grepped and re-read against the source, with
the file and line that settles it written into the row. Gates at that
measurement: `cargo fmt --all --check` clean; `cargo test --workspace` **6439
passed / 0 failed / 9 ignored**; `xtask check` and `xtask consumer` both pass;
`cargo clippy --workspace --all-targets` **360** warnings. What the campaign did
to this page is recorded in `docs/debt-closure.md`; the short version is that
**three rows were closed by deleting their subject** (listed as four entries at
the bottom, since one row named two independent caches) and are summarised there
rather than kept in the tables, and thirteen rows had moved and are
corrected in place — each marked `~~old claim~~ — **CLOSED**`, or split so that
each half says what is actually so.

The lesson the `ch` row taught is worth stating at the top: **a page that
over-claims brokenness misleads a reader deciding what to build on just as badly
as one that over-claims completeness.** And the lesson the *clamp* row taught,
twice: **grepping a symbol you already suspect cannot enumerate.** That row was
widened from "flex" to "flex and grid" by one re-measure and was still one word
too narrow, because the second pass grepped the two algorithms it had been told
about instead of grepping the *call*. Do not trust a row here without re-running
its grep, and prefer a grep that enumerates over one that confirms.

## Unwired by construction: the re-export barrel

`obscur-kit/src/lib.rs` is `pub use X as y;` and nothing else. A crate whose only
path to the outside is that file is exported, compiles, and is called by nothing.

The table below is what the check found. Three rows are still that shape; the
fourth, `obscur-testkit`, used to be the worst of them and no longer is — it is
kept here so the correction is visible next to the claim it replaces.

| **`@container`** | parses; ~~then lowers to `RuleCondition::Never`~~ — **the mechanism named here is stale, the outcome is not.** `lower_container_query` lowers a non-empty query to a real `RuleCondition::All` of `FeatureQuery`s on `ConditionAxis::ContainerWidth`/`ContainerHeight` (`obscur-css/src/compiler/condition_lowering.rs:52-63`); only an empty query, or a feature name it does not recognise, still reaches `Never`. What makes the rule fail closed now is one level down: `FeatureQuery::holds` reads `env.container_width()`, and when that is `None` it returns `!self.axis.is_container()` — **false for a container axis** (`obscur-style/src/matching/rule_condition.rs:84-92`). So the rule still never matches — but it fails closed at *evaluation* for want of a container size, not at *compile* for want of a lowering, and wiring it is now one call rather than a new code path. | **UA stylesheet vocabulary** | **Was: a third of the sheet matched nothing.** This page's own subject, in the one place a reader would never look for it — a *stylesheet* is not a type, so no grep for a zero-caller symbol would ever have found it. **Seven of the sheet's 48 rules** could not reach anything the Rust API builds: `table`, `th`, `td`, `tr:hover` against a widget whose rows and cells carried a private `role` *property* CSS cannot see; `img` against a primitive that emitted no name at all; `.placeholder` against a class nothing emits, when §4.16 makes the hint a synthetic part reachable only through `::part()`; `.select-option.disabled` against a per-option state `Select` does not have. | **Base-element control tags** | **Was: *"they bind to the shipped widget's `ComponentId`, but nothing registers a factory for the built-in widget ids, so the widget's own `view()` — its indicator sub-part, its `:checked` class — never runs. The id is a handle with nothing mounted under it."*** Five of the six now mount, and the sixth is a refusal with a reason. `<input>`, `<textarea>`, `<checkbox>`, `<radio>`, `<select>`, `<table>` bind to the shipped widget's `ComponentId` instead of falling through to `Container`, so an authored `<checkbox>` is a checkbox to the cascade, to hit-testing and to the accessibility tree. **`<checkbox>`, `<radio>`, `<select>`, `<input>` and `<textarea>` are now also mounted controls** — a `…Props` + `…Component` + `…Factory` trio ships in `obscur-widgets` for each, `KitBootstrap::install_builtin_components` registers them by default, and `App`/the layer runner call it. An authored `<checkbox label="…" checked/>` renders the `.checkbox-box` indicator the UA sheet fills, with `:checked` still matching the host; `<radio label="…" checked/>` renders its `.radio-dot`; `<select options="Alpha, Beta" open/>` renders the `.select-header` and the `.select-list` of rows, and a `<select … open disabled/>` still reaches `select:disabled .select-option`; `<input value="abc"/>` renders its editable run, where before an authored value was invisible. `<input>` and `<textarea>` are **one** registration — they share `Input::COMPONENT_ID`, and which of them a node is rides on its local name, so `EditableField::is_multiline` still tells them apart and an authored textarea's `Enter` still inserts a newline. **`<button>` is mounted too, and it is the one whose content is the author's**: `ButtonComponent` renders the §2.12 default-slot outlet with `label="…"` as its fallback, so `<button>Save</button>` keeps its text, `<button><span>press</span></button>` keeps its span, `<button label="Save"/>` finally renders the label the `.okui` compiler already required, and `Button::new("Save", cmd).view()` — which states the label as a child — renders exactly the tree it did before. What stops is the *checking* — an unregistered or misspelled tag mounts nothing with no diagnostic, and the `okui!` macro cannot ever check it (the registry is a runtime value of trait objects; the macro runs while that crate compiles). And one thing a shipped widget cannot do: **use `#[derive(Contract)]`.** The derive expands to `::obscur_kit::…` paths and §3.16 forbids an internal crate from depending on the facade, so each `…Props::contract()` is written out by hand and pinned against the derive's own output by `obscur-kit/tests/builtin_components.rs`. The derive also could not express the decoding: a reserved boolean attribute is set by *presence* (`<checkbox checked/>` lowers to `Null`, which `:checked` reads as set and `decode_optional::<bool>` reads as absent), a checkbox has a third, mixed state no boolean carries, and a `<select>`'s options are a *list* — which a `ViewValue` has no variant for, so they travel as a delimited string that the props struct splits (comma-separated when authored, and joined on U+001F by `Select::view` so a Rust caller's label containing a comma still survives). **Re-measured**: `impl Component for` now has exactly five occurrences in a crate an application links — all five in `obscur-widgets/src/{button,checkbox,input,radio,select}/*_component.rs` — each with a `ComponentFactory` beside it, and the hand-written contracts are still pinned by `obscur-kit/tests/builtin_components.rs` (29 tests). **The missing check is still missing, and here is exactly where**: `ComponentRenderPass::render` does `let Some(mounted) = self.components.get_mut(node) else { continue; }` (`runtime/component_render_pass.rs:93`), so a node bound to an id nothing registered is skipped in silence — the one `Diagnostic` this pass now raises is `view.undeclared_slot` (`:215`), which is about slot *names*, not about the mount |
| **`<VirtualFor>`** | compiles on both front ends and emits the §4.9 marker the runtime windows. The template carries **no item binding**, so every realized row is identical; per-item rows still need `register_virtual_list`. Re-confirmed at the seam: `lower_virtual_collection` collects the element's children into a `ViewFragment` and hands it to `ViewNode::virtual_collection(DEFAULT_VIRTUAL_ROW_EXTENT, template)`, dropping the `each` expression entirely (`okui-compiler/src/bridge/ui_ir_view_bridge.rs:95-103`); the runtime then repeats that one template through `realize_virtual_collections`, while the *builder* path — the one that can differ per row — is reachable only from `register_virtual_list` (`runtime/virtual_lists.rs:170-230`) |
| **Slots** | **Was: *"No shipped component declares a slot: no shipped widget is a `Component`."*** Both halves of that sentence are false now, and only the first half needed slots to fix it. Declared, enforced and projected. **One shipped component declares a slot, and it is the default one.** `Checkbox`, `Radio`, `Select` and `Input` declare none, and for a reason rather than an omission: each renders content of its own (a label, a dot, a list of rows built from labels, an editable run), so each contract is `ChildContract::None` and an authored child under one is a compile error naming the prop spelling instead. `Button` is the control where that answer was not available — `<button>Save</button>` is the author's own markup, and its only child is a *text run*, which carries no properties and so can never name a slot. So §2.12 gained the piece it was missing: **the default slot.** An outlet naming no slot takes the content that names none (text runs included); an outlet nothing fills renders its own children as a **fallback**, which is how `<button label="Save"/>` and `<button>Save</button>` are one component rendering one position; and `ButtonProps::contract()` declares that slot under the reserved `DEFAULT_SLOT` name, `SlotCardinality::Many`, `ChildContract::Any`. The retention gate moved with it: the reconciler kept a host's children only when one of them named a slot, which no default-slot content ever does, so it now also keeps them for any id a component can be mounted under (`may_project_content` — the widget range and the top-bit user range; every `div` in a document is a primitive below both). Two things that used to stop here no longer do. ~~"an outlet's *name* is checked against nothing, so a component rendering `<slot name="hedaer"/>` receives nothing"~~ — `SlotMismatch::find` compares both sides against the contract and `ComponentRenderPass` reports `view.undeclared_slot`, at the one point where both halves exist: after the render, before projection substitutes the outlets away. It is checked from the author's side too, since a misspelled `slot="…"` is dropped just as quietly. ~~"the spec still does not state the default slot — §2.12 lists 'named slots' only"~~ — §2.12 now states it: what it is, that a text run makes it necessary rather than convenient, that it is declared under a reserved symbol no author-written name can produce, and that names are checked against the contract. `#[derive(Contract)]` gained `slot(default)`, so `spec_ch2_contracts`'s `a_default_slot_and_a_named_slot_partition_the_children` is **restored** to its full form and `ButtonProps`'s hand-written contract is now compared to the derive's output *whole*. Where it stops: the default slot and outlet fallback content still have no authored spelling, so `.okui` refuses `<slot/>` and children on an outlet — with diagnostics that say why rather than saying the feature is absent. **Re-confirmed at all three points**: `DEFAULT_SLOT` is a reserved symbol (`obscur-view/src/view/slot.rs:14`), `ButtonProps::contract()` declares it (`widgets/src/button/button_props.rs:33`), and the two refusals are pinned in `okui-compiler/src/compile.rs`'s `a_malformed_outlet_makes_the_compile_report_errors` — `<div><slot/></div>` → *"requires a `name`"*, `<slot name="h"><b>f</b></slot>` → *"takes no children"* — through the same `has_errors()` gate `obscur-kit`'s `build.rs` panics on |
| **Telemetry** | `PerformanceSpan` carries no duration; the DevTools protocol has no timing field. `OBSCUR_FRAME_STATS` is the honest profiler. Re-confirmed by reading the struct: `PerformanceSpan { name, subsystem, attribution }` and nothing else (`obscur-diagnostics/src/performance/performance_span.rs:8-15`) — it is `Copy`, which is only possible because there is no clock in it — and a grep for `duration`/`micros`/`elapsed` across `obscur-devtools-protocol/src` returns nothing |
| **Diagnostics** | **Half of this is closed.** ~~"Reachable, not reached"~~ — a real sink ships and is reached: `DiagnosticEventSink` (`obscur-kit/src/devtools.rs:323-350`) implements `DiagnosticSink` by pushing each `Diagnostic` onto the DevTools `EventQueue`, and two shipped examples install it through `runtime.set_diagnostic_sink(…)` (`examples/showcase_window.rs:150`, `examples/wireframe_live_window.rs:184`), as does `tests/devtools_live.rs:593`. `obscur-diagnostics` also ships `ChannelSink`/`DiagnosticChannel` with filtering and a buffer policy. What is still true is the **default**: `UiRuntime::new` installs `Box::new(NullDiagnosticSink)` (`runtime/ui_runtime/construction.rs:81`), and neither shipped runner replaces it — `set_diagnostic_sink` has **zero** call sites in `crates/facade/obscur-kit/src/`. So a plain `App` or `LayerApp` still drops every diagnostic its producers construct; a host that wants them has one line to write, and the two examples are the worked version of it |
| **Invalidation** | **Half of this is closed too.** ~~"a boolean per phase everywhere else. The phases take no dirty set"~~ — **layout takes one.** `LayoutClassifier` returns `LayoutPhase::Invalidated(LayoutInvalidation)`, a per-node set, and `ArrangePhase` passes it straight into `layout_invalidated(…, dirty)` so the coordinator drops exactly the measure- and arrange-cache entries that set can have invalidated and serves every other node without re-measuring (`runtime/arrange_phase.rs:139-153`). The classifier's own comment records what changed: *"Reading only the boolean — and dropping the per-node set — is what used to make `LayoutInvalidation` write-only and layout all-or-nothing"* (`runtime/layout_classifier.rs:141`). So style **and** layout are per-node. What is still a boolean: `FramePlan` is four `bool`s (`reconcile`/`style`/`layout`/`compose`, `runtime/frame_plan.rs`), and **compose takes no dirty set at all** — `ComposePhase::run` receives the frame context, the computed styles, the editing view and the hovered node, and repaints the scene whole (`runtime/compose_phase.rs:79-86`). `LayoutPhase::Full` still passes `None`, which drops both caches and reproduces the historical all-or-nothing pass byte for byte |
| **Docking** | panels are described and laid out; re-docking by drag is not built. Sharper: re-docking *is* built as an API — `Docking::dock(&mut self, id, side)` moves a panel between sides (`widgets/src/docking/docking.rs:106`) — so what is missing is only the gesture that would call it. No drag session, no drop target, no hit-tested edge |
| **Plugin tier** | an honest, well-labelled, entirely unbuilt skeleton — and **more unbuilt than this row said**. The nine `crates/plugin/*` crates are workspace members that **nothing depends on**: `grep -rn obscur-plugin --include=Cargo.toml crates/` returns hits only inside `crates/plugin/` itself, and unlike `obscur-routing` they are not even re-exported from the facade barrel, so there is no path to them from `obscur-kit` at all. ~~"The `sandbox` module *describes* a sandbox; it does not enforce one, and the crate docs say so"~~ — **there is no `sandbox` module.** A case-insensitive grep for `sandbox` across `crates/` finds it only in the resource loader (`FsResourceLoader`'s root confinement, which is real and enforced) and in `KitBootstrap::install_image_resources`. What the row was reaching for lives in `obscur-plugin-host/src/policy/` and `…/capability/` — `CapabilityPolicy`, `ActivationPolicy`, `ResourceBudget`, `CapabilityIssuer`, `CapabilityRevoker`, `DelegationGraph` — and those are the honest labelling: `capability_policy.doc/CapabilityPolicy.md` reads, in full, *"Placeholder for the `CapabilityPolicy` entity. ## Known defects

| | |
|---|---|
| **Every algorithm but flow clamps its own border box** | a flex container clamps rather than overflowing, so `width: 100%` + padding gives a different used width under flex than under block. The chain `[1000, 1020, 960]` is internally inconsistent. ~~"Flex clamps its own border box"~~ was widened to ~~"Flex — and grid —"~~ by the 2026-08 re-measure and **was still wrong, in the same direction, for the same reason**: that pass grepped the two algorithms it had been told about rather than grepping the call. Enumerating `\.constrain(` across `obscur-layout/src/` instead finds **four** algorithms clamping a content-derived border box — flex (`flex_layout.rs:407`, `:611`), grid (`grid_layout.rs:545`), **`custom_layout.rs:69`** and **`docking_layout.rs:174`** — against `constrain_allowing_overflow(border_box)` in flow alone (`flow_layout.rs:432`, `:650`). A fix belongs at **all four** call sites. (`positioned_layout.rs:61` and `constraint_layout.rs:58` also call `constrain`, but on an explicitly computed width/height rather than a content-derived border box, which is the case where clamping is correct — they are not part of the defect.) Note also that nothing pins the numbers: `tests/percentage_in_padded_parent.rs`'s flex case uses `width: 800px` on the outer box, which is precisely the case the clamp cannot bite, so the block-vs-flex divergence is unasserted in either direction. Related and *fixed*: an `auto` basis now resolves to max-content, so a plain item no longer eats the free space its growing siblings asked for |
| **Indefinite axes and percentages** | percentages should resolve only against a definite size; the constraint model does not carry the distinction everywhere. Related and *fixed*: a percentage block-size resolved against the space a child's *siblings* had left over, compounding down the chain (two `height: 100%` siblings measured 240/0). Flow now attaches the containing block's own definite content size as `BoxConstraints::percent_basis`, separately from the offer. Also *fixed*: a grid item's children saw the grid **container's** content box rather than the item's grid area (a `width: 100%` item was its 211px track while its child resolved `50%` against 432), and grid now states each item's area as `LayoutOutput::child_percent_basis`. Also *fixed*, the same defect in flex: an item's cross size was measured with the main axis pinned to its used size and no basis, so a `width: 50%` item re-read that pinned number as its containing block and laid its own content out at half again (a wrapping inner row reported two lines, 120, where its arranged self has one, 60). The cross measure now states the flex container's content box, which is the number the item's main size was already resolved against. **Both of the remainders this row used to carry are now closed too.** (i) The grid states each item's area on **both** axes, not just the inline one — `specs/w3c/css-grid-2.txt:3527` is explicit that by the time items are laid out "each grid area's width and height are considered definite for this purpose", which answers by phase order the worry (a content-sized row's extent is the item's own height) that had kept the block axis unstated; a `height: 100%` item's child read 96, half the container's content height, where it should read half the item's 100px row (`tests/percentage_in_grid_item.rs`). (ii) A percentage against a genuinely indefinite axis now **behaves as auto** (`specs/w3c/css-sizing-3.txt:554`) instead of folding against the offer: flow states an indefinite block size as `f32::INFINITY`, which `Dimension::resolve` already answers `None` to, so the value arrives on the `auto` path every caller already had. Two `height: 50%` siblings under an `auto`-height parent measured `(225, 112.5)` — half the offer, then half of what that left — and now measure the `auto` answer, verified equal to the `auto` spelling rather than to a constant (`tests/percentage_against_indefinite.rs`). The rule now reaches the three intrinsic-sizing probes this row used to name: flex's `probe_main` states an infinite main basis (its comment used to read "this engine has no behave-as-auto"; it does now), and grid's step-2 item measure states `(area, ∞)` because the rows are sized *from* that measure and the block axis is genuinely indefinite at that moment. What remains is narrower than the heading: `min-content`/`max-content` as a *cross* size still reads as "not a length" and so is treated as `auto` where css-flexbox scopes stretch to "computed cross size is auto" — a separate sentence, separately open. **Re-measured, and the mechanism is one line**: `Dimension::resolve` answers `None` for `Auto | MinContent | MaxContent | FitContent` alike (`model/dimension.rs:23-25`), and flex derives `cross_is_auto` from exactly that (`flex_layout.rs:446-450`), so the three keywords are indistinguishable from `auto` at the point the decision is made. `Dimension::is_intrinsic` already exists to tell them apart — the cross path simply does not ask |
| **No real min/max-content pair** | ~~"intrinsic sizing computes one number where the algorithm wants two"~~ — **stale as stated; the real cost is a re-measure, not a missing number.** Both numbers are computed where the algorithms need them. `intrinsic_inline_size` answers `MinContent` by probing at offer `0.0` and `MaxContent` at `UNBOUNDED` (`algorithm/intrinsic_inline.rs:46-47`), and flow calls it three times per box — once for `width`, once for `min-width`, once for `max-width` (`flow_layout.rs:138`, `:152`, `:159`). Grid goes further and keeps an actual record: `Contributions { auto, min, max }` (`grid_track_sizing.rs:64`), filled by one `measure_child` per intrinsic kind the item's span crosses, at offers `loose` / `0` / `∞` (`grid_layout.rs:198-217`). What is genuinely absent is a **pair returned by one pass**: each keyword is an independent full re-measure of the same subtree, so a box that needs both pays for both. ~~and the type that would carry them together — `IntrinsicSize`, behind `IntrinsicMeasure::intrinsic_size` — is unreachable in production~~ — **that half is now moot: `IntrinsicSize` is deleted** (see *Closed by deletion*, below). It was not the pair type this row wants; grid's `Contributions { auto, min, max }` already is one, is filled every frame a grid lays out, and is reachable. Keeping a second, unreachable spelling of it against a future fix would have been the same defect the rest of this page records. Two consequences the old wording hid: the numbers are right, and the fix is a caching/API change rather than an algorithm one |

## Closed by deletion

Four rows left this page by having their subject removed. They are summarised
here rather than kept in the tables above, because a page about what is not wired
should not be mostly about what no longer exists. The full reasoning, the
verification that preceded each removal, and the refusals are in
`docs/debt-closure.md`; each deletion also left a `// why` comment at its own
site, because the code cannot carry the reason once the code is gone.

| Was | Verdict |
|---|---|
| Vello `GlyphCache` / `PathCache` / `TextureCache` | ~~dead scaffolding — Vello's own atlases make them redundant. To delete, not to bound~~ — **deleted.** `cache/` entire: 40 files, 337 lines, 10 unit tests. Unfillable by construction: `vello_encoding` keeps and prunes its own glyph cache, `vello` holds the `image_atlas`, and `PathCache` had no key at all because `obscur_scene::Path` holds floats and cannot derive `Hash` |
| `IntrinsicMeasure`, `MockIntrinsicMeasure`, `LayoutEnvironment`, `IntrinsicSize` | ~~the layout port leaves are documented as routing to. They do not~~ — **deleted**, and the seven documentation claims that asserted the routing are corrected. `port/` entire plus `model/intrinsic_size.rs`: 30 files, 328 lines, 11 unit tests. Both leaf kinds already have a road and neither has the port's shape; wiring it would have been a second spelling of `ChildMeasurer`, and impossible besides, since algorithms address children by index and the port by `NodeId` |
| `StyleCache`, `CacheEntry` (style) | ~~dead; both *could* genuinely be wired~~ — **deleted**, and the "could" was the error. The style phase already resolves only the `StyleInvalidation` set, pinned at `style.resolved == 1` by `incremental_restyle.rs`. `StyleCache` keyed on a tree-wide `VersionStamp`, so every node would have missed together where the live per-node set misses one |
| `LayoutCache`, `CacheEntry` (layout), `LayoutResult` | ~~same row~~ — **deleted.** `MeasureCache`/`ArrangeCache` already ship and are pinned at `arranged_count() == 0` by `layout_coordinator.rs`. `LayoutCache::get_arrange` keyed on the `NodeId` alone where `ArrangeKey` carries five components, and held one entry per node where a node is measured under two constraint sets in the same pass. Wiring it would have been a regression, not a saving. Together with the style half: 55 files, 637 lines, 22 unit tests |

The four share one shape, and it is worth naming because it is what this campaign
mostly found: **not unanalysed code, but code whose successor already shipped past
it.** In every case the live mechanism was later and better keyed than the dead
one, and in two of them the dead type's own documentation had already worked out
the whole case and stopped at "the decision is the owner's".

## What this page is not

It is not a roadmap and not an apology. Most of these are deliberate: failing
closed on `@container` is better than matching wrongly, and a CPU renderer that
approximates GPU effects by policy is better than one that pretends. The list
exists so that reading a type's presence in the re-export barrel does not mislead
you into thinking something runs.

If you need one of these wired, the gap is usually small and specific — most
entries above are "no caller", not "no implementation".

It is also **not a page you may read without checking**, and the two re-measures
behind it are the argument. The 2026-08 pass found thirteen rows that had moved
and nobody had come back — in both directions. `ch` had been fully closed for
some time while this page still told a reader it contributed `0`; `@container`
had grown a real lowering while this page still named the `Never` it no longer
emits; the plugin tier was described through a `sandbox` module that does not
exist. But `obscur-system` had *fewer* adapters than claimed, and the flex
border-box clamp turned out to be a grid defect too.

The 2026-08-04 pass then found that the pass before it had **itself** left three
things wrong: the clamp row was widened once and was still too narrow (four
algorithms, not two), the `ch` row named three of four production supply sites,
and the gamepad row counted the haptic file's tests as its own. None of those was
carelessness; all three are the same mechanical limit, which is the most useful
thing on this page:

> **A grep that confirms a symbol you already suspect cannot enumerate.** It
> finds the first hop and stops. Three separate rows were fixed only by grepping
> the *call* (`\.constrain(`), the *construction* (`ShapedChMetrics::new`) or the
> *directory* rather than the name someone had already written down — and
> `HitTest`, `HitChain` and the whole `pass/` island were absent from this page
> for exactly as long as nobody happened to suspect them.

The convention when you find one: strike the old claim, write what the
measurement was, and cite the file and line — so the next reader can tell a
verdict from a memory. And when the row is a *count* or a *set*, enumerate it;
do not confirm it.
